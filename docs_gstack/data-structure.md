## Overview

This document defines every entity the NEST demo platform must store in the database, the fields each entity requires, and the relationships between them. All monetary values are stored as BigInt in kobo. The wallet balance is always a calculated read model — never an independently editable balance.

**Key corrections from v1.0:**
- Funding target: ₦100,000,000 (not ₦70,000,000)
- Minimum investment: ₦500,000 (not ₦1,500,000)
- Platform fee: 2% of investment amount (not 5%)
- Management fee: up to 8% of rent collected (not 8% of AUM)
- 8% AUM fee: removed — must not appear anywhere
- Real investor data: not in any seed entity; illustrative fictional data only
- Added: termsConsentVersion, termsConsentAt for investor consent tracking
- Added: allocationState (PENDING/REFUNDED/TRANSFERRED) for fallback tracking

## 1. Core Entities

### 1.1 User

Represents an authenticated user. Created on first Clerk sign-in via profile mirror.

| Field | Type | Notes |
|---|---|---|
| id | UUID (PK) | Generated by Postgres |
| clerkId | String (UNIQUE) | From Clerk; used for auth lookup |
| email | String (UNIQUE) | Synced from Clerk at creation |
| name | String? | Display name |
| role | Enum: INVESTOR, ADMIN | NEST-owned; not stored in Clerk |
| kycStatus | Enum: PENDING, VERIFIED, REJECTED | Demo state only; admin-controlled; not real KYC |
| isLocked | Boolean (default: false) | Account lock for admin override |
| termsConsentVersion | String? | Version of terms accepted at investment (e.g., "v1.0-2026-09-16") |
| termsConsentAt | DateTime? | Timestamp of terms/risk consent (server-recorded at investment confirmation) |
| allocationState | Enum: ACTIVE, REFUND_REQUESTED, REFUNDED, TRANSFERRED | For pilot fallback tracking — tracks whether investor has exercised fallback option |
| createdAt | DateTime | |
| updatedAt | DateTime | |

**Indexes:** clerkId (UNIQUE), email (UNIQUE), kycStatus

**Notes:**
- `kycStatus: VERIFIED` is a demo state only — it is not real KYC verification
- `termsConsentVersion` and `termsConsentAt` are set server-side at the moment of investment confirmation — never from client input
- `allocationState` tracks the pilot fallback process per requirements.md Section 6.4

### 1.2 Wallet

One wallet per user. Balance is never stored as an editable column — it is calculated from the ledger.

| Field | Type | Notes |
|---|---|---|
| id | UUID (PK) | |
| userId | UUID (UNIQUE FK → User.id) | One wallet per user |
| currency | String (default: "NGN") | |
| availableBalanceKobo | BigInt (default: 0) | Read model; updated within same transaction as ledger posting; must always equal SUM(POSTED LedgerEntries.amountKobo) for this wallet |
| isLocked | Boolean (default: false) | Admin can lock wallet to prevent operations |
| createdAt | DateTime | |
| updatedAt | DateTime | |

**Indexes:** userId (UNIQUE)

**Critical invariant:** `availableBalanceKobo == signed SUM(POSTED ledger entries where walletId = this.id)` after every mutation. This is enforced in the ledger service.

### 1.3 LedgerEntry

Immutable, append-only record of every wallet movement. The ledger is the source of truth for money.

| Field | Type | Notes |
|---|---|---|
| id | UUID (PK) | |
| walletId | UUID (FK → Wallet.id) | |
| amountKobo | BigInt | Positive = credit; negative = debit. Cannot be zero. |
| type | Enum: DEMO_CREDIT, INVESTMENT_DEBIT, PLATFORM_FEE, DISTRIBUTION_CREDIT | |
| status | Enum: POSTED | All entries are POSTED immediately; no pending state in demo |
| reference | String (UNIQUE) | Idempotency key; duplicate reference returns existing entry, no new write |
| label | String? | Human-readable label; "DEMO CREDIT — NOT A PAYMENT" for demo credits |
| relatedEntityId | String? | Investment ID, Distribution ID, etc. |
| relatedEntityType | String? | "INVESTMENT", "DISTRIBUTION", "DEMO_CREDIT" |
| createdAt | DateTime | Immutable — never updated |

**Indexes:** walletId, reference (UNIQUE), (walletId, createdAt) composite for pagination

**Rules:**
- No UPDATE or DELETE on LedgerEntry — append-only
- amountKobo ≠ 0 (zero-value entries are invalid)
- reference must be globally unique (not just per wallet)
- DEMO_CREDIT entries must have label = "DEMO CREDIT — NOT A PAYMENT"

### 1.5 Investment

Records a confirmed fractional holding by a user in a property.

| Field | Type | Notes |
|---|---|---|
| id | UUID (PK) | |
| userId | UUID (FK → User.id) | |
| propertyId | UUID (FK → Property.id) | |
| amountKobo | BigInt | The investor's principal investment (before platform fee) |
| platformFeeKobo | BigInt | Platform fee deducted (2% of amountKobo) |
| totalDebitedKobo | BigInt | amountKobo + platformFeeKobo (total debited from wallet) |
| ownershipPercent | Decimal | principal (amountKobo) ÷ property.fundingTargetKobo × 100; e.g. ₦5M ÷ ₦100M = 5.0% |
| status | Enum: PENDING, CONFIRMED, CANCELLED | CONFIRMED after successful atomic transaction |
| receiptNumber | String (UNIQUE) | e.g., "INV-20260916-001" |
| idempotencyKey | String (UNIQUE) | Client-generated UUID; prevents duplicate investments |
| termsConsentVersion | String | Version of terms/risk disclosure accepted at time of investment |
| termsConsentAt | DateTime | Server-recorded timestamp of consent |
| isDemoInvestment | Boolean (default: false) | Flag for demo vs live pilot records |
| createdAt | DateTime | |
| confirmedAt | DateTime? | Set when status → CONFIRMED |

**Indexes:** userId, propertyId, idempotencyKey (UNIQUE), (userId, propertyId), receiptNumber (UNIQUE)

**Rules:**
- An Investment is only CONFIRMED after the atomic transaction commits
- amountKobo ≥ property.minInvestmentKobo
- amountKobo ≤ property.maxInvestmentKobo
- totalDebitedKobo ≤ wallet.availableBalanceKobo at time of transaction
- amountKobo ≤ property.fundingTargetKobo - property.fundingRaisedKobo (remaining capacity)
- Same idempotencyKey cannot create a second Investment
- `isDemoInvestment: true` on all demo/seeded investments

### 1.6 Distribution

Records a quarterly rental income distribution event for a property.

| Field | Type | Notes |
|---|---|---|
| id | UUID (PK) | |
| propertyId | UUID (FK → Property.id) | |
| period | String | e.g., "Q4-2026-DEMO" |
| totalRentCollectedKobo | BigInt | Total rent collected by property management |
| managementFeeKobo | BigInt | Up to 8% of totalRentCollectedKobo (not % of AUM) |
| netDistributedKobo | BigInt | totalRentCollectedKobo - managementFeeKobo |
| investorCount | Integer | Number of investors credited |
| executedByUserId | UUID (FK → User.id) | Admin who executed the distribution |
| isDemoDistribution | Boolean (default: false) | Flag for demo distributions |
| createdAt | DateTime | |

**Unique constraint:** (propertyId, period) — prevents duplicate distribution for same property/period

**Rules:**
- netDistributedKobo = totalRentCollectedKobo - managementFeeKobo (exactly)
- Sum of all investor allocation LedgerEntries must equal netDistributedKobo (exactly — no rounding loss allowed; use integer arithmetic)
- managementFeeKobo is calculated as a percentage of rent COLLECTED, not of total property value
- `isDemoDistribution: true` on all demo distributions

### 1.8 AuditLog

Append-only record of all admin actions and money-sensitive operations.

| Field | Type | Notes |
|---|---|---|
| id | UUID (PK) | |
| actorUserId | UUID? (FK → User.id) | The user who performed the action (null for system actions) |
| action | Enum: USER_VERIFIED, USER_REJECTED, DEMO_CREDIT_ISSUED, INVESTMENT_CREATED, INVESTMENT_CANCELLED, DISTRIBUTION_EXECUTED, WALLET_LOCKED, WALLET_UNLOCKED | |
| entityType | String | "USER", "INVESTMENT", "DISTRIBUTION", "WALLET", etc. |
| entityId | String? | ID of the affected entity |
| metadataJson | Json? | Additional context (amounts, property IDs, etc.) — no PII |
| ipAddress | String? | Optional; do not log if PII risk |
| createdAt | DateTime | Immutable |

**Indexes:** actorUserId, (entityType, entityId), createdAt

**Rules:**
- Append-only; no UPDATE or DELETE
- Every admin action creates an AuditLog entry
- Every investment creates an AuditLog entry
- Every distribution creates an AuditLog entry
- No personally identifiable information (PII) in metadataJson

## 3. Kobo Conversion Reference

All monetary amounts stored as BigInt in kobo (₦1 = 100 kobo):

| Display Value (₦) | Stored Value (kobo) | BigInt Literal |
|---|---|---|
| ₦100,000,000 (target) | 10,000,000,000 | 10000000000n |
| ₦10,000,000 (max) | 1,000,000,000 | 1000000000n |
| ₦5,000,000 | 500,000,000 | 500000000n |
| ₦2,000,000 | 200,000,000 | 200000000n |
| ₦500,000 (min) | 50,000,000 | 50000000n |
| ₦40,000 (2% of ₦2M) | 4,000,000 | 4000000n |
| ₦10,000 (2% of ₦500K) | 1,000,000 | 1000000n |
| ₦1 | 100 | 100n |

Conversion: `amountNaira × 100 = kobo`

## 4. Key Design Decisions

### 4.1 Immutable Ledger
Wallet balance is never stored as an editable column. It is always the signed SUM of POSTED LedgerEntry rows. The `availableBalanceKobo` on the Wallet row is a read-model cache updated within the same atomic transaction as each ledger posting — it must always equal the ledger SUM.

### 4.2 BigInt for Money
JavaScript `number` has floating-point precision issues. All persisted money is BigInt kobo. Convert only at display boundaries.

### 4.3 Idempotency Keys
- Investments: client-generated UUID in `idempotencyKey` field
- Distributions: natural composite key `(propertyId, period)` — unique constraint
- Demo credits: `reference` field — unique constraint
- Paystack webhooks (if implemented): provider reference — unique constraint

### 4.4 Terms Consent — Server-Recorded
`termsConsentVersion` and `termsConsentAt` are set by the investment service, not from client input. The client sends a boolean "I have checked all boxes," but the server records which version and when. This creates an auditable consent record.

### 4.5 Demo vs. Live Record Separation
`isDemoProperty`, `isDemoInvestment`, and `isDemoDistribution` flags allow the database to clearly separate demo/seeded test records from any future live pilot records. Queries serving investor-facing screens must filter appropriately.

### 4.6 Soft Deletes Not Used
No soft deletes. Financial records (LedgerEntry, Investment, Distribution, AuditLog) are append-only and immutable. User accounts can be anonymised (null out PII fields) while retaining financial records for audit purposes.

### 4.7 Fee Calculation Rules
- Platform fee: `amountKobo × 0.02` (2%, integer arithmetic — truncate, do not round up)
- Management fee: `totalRentCollectedKobo × managementFeePercent / 100` (integer arithmetic)
- Net to distribute: `totalRentCollectedKobo - managementFeeKobo`
- Investor allocation: `netDistributedKobo × (investment.amountKobo / property.fundingTargetKobo)` (integer arithmetic; any rounding remainder credited to the largest investor or held in reserve — document the rule)

## 6. Worked Example — Illustrative Demo Investment

**Scenario:** Demo investor Adaeze invests ₦2,000,000 in the illustrative test property.

**1. User (Adaeze — fictional demo account)**
```
id: "user-adaeze-demo"
kycStatus: "VERIFIED"
role: "INVESTOR"
isDemoAccount: true (implied by fictional email domain)
```

**2. Property (Illustrative Demo)**
```
id: "prop-demo-001"
fundingTargetKobo: 10000000000n (₦100M)
fundingRaisedKobo: 500000000n  (₦10.5M — pre-seeded from other demo investors)
minInvestmentKobo: 50000000n    (₦500K)
maxInvestmentKobo: 1000000000n  (₦10M)
platformFeePercent: 2.0
isDemoProperty: true
```

**3. Atomic Investment Transaction**
```
BEGIN TRANSACTION
  SELECT wallet FOR UPDATE WHERE userId = "user-adaeze-demo"
  → availableBalanceKobo: 500000000n (₦5M demo credit)

  Validate:
    amountKobo: 200000000n (₦2M) ≥ 50000000n ✓
    amountKobo: 200000000n (₦2M) ≤ 1000000000n ✓
    platformFeeKobo: 4000000n (₦40K, 2% of ₦2M principal)
    totalDebitedKobo: 204000000n (₦2.04M) ≤ 500000000n ✓

  SELECT property FOR UPDATE WHERE id = "prop-demo-001"
  → fundingRaisedKobo: 500000000n
  → remainingCapacity: 10000000000n - 500000000n = 9500000000n
  → 200000000n ≤ 9500000000n ✓

  INSERT LedgerEntry:
    walletId: "wallet-adaeze", amountKobo: -200000000n, type: INVESTMENT_DEBIT
    reference: "INV-ADAEZE-20260916-001"

  INSERT LedgerEntry:
    walletId: "wallet-adaeze", amountKobo: -4000000n, type: PLATFORM_FEE
    reference: "FEE-ADAEZE-20260916-001"

  UPDATE Wallet SET availableBalanceKobo = 500000000n - 200000000n - 4000000n = 296000000n

  INSERT Investment:
    userId: "user-adaeze-demo"
    propertyId: "prop-demo-001"
    amountKobo: 200000000n (₦2M)
    platformFeeKobo: 4000000n (₦40K)
    totalDebitedKobo: 204000000n (₦2.04M)
    ownershipPercent: 200000000 / 10000000000 × 100 = 2.0  (principal ÷ target)
    status: CONFIRMED
    receiptNumber: "INV-20260916-001"
    idempotencyKey: [client-generated UUID]
    termsConsentVersion: "v1.0-2026-09-16"
    termsConsentAt: [server timestamp]
    isDemoInvestment: true

  UPDATE Property SET fundingRaisedKobo = 500000000n + 200000000n = 700000000n (?7M total; 7.0% of ?100M target)

  INSERT AuditLog:
    actorUserId: "user-adaeze-demo"
    action: INVESTMENT_CREATED
    entityType: "INVESTMENT"
    entityId: [investment id]
    metadataJson: { amountKobo: 200000000, propertyId: "prop-demo-001", isDemoInvestment: true }

  INSERT Notification:
    userId: "user-adaeze-demo"
    type: INVESTMENT_CONFIRMED
    title: "Investment Confirmed — TEST MODE"
    message: "Your ₦2,000,000 demo investment is confirmed. This is a test-mode demo — no real money involved."

COMMIT TRANSACTION
```

**4. Post-transaction verification:**
```
LedgerEntry SUM for Adaeze wallet: 500000000n - 200000000n - 4000000n = 296000000n
Wallet.availableBalanceKobo: 296000000n (₦2,960,000) ✓
Property.fundingRaisedKobo: pre-seeded 500000000n + Adaeze principal 200000000n = 700000000n (₦7M — 7.0% of ₦100M target)
Investment.status: CONFIRMED ✓
```
